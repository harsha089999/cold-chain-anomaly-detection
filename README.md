# Cold Chain Anomaly Detection

[![Run project](https://github.com/harsha089999/cold-chain-anomaly-detection/actions/workflows/run.yml/badge.svg)](https://github.com/harsha089999/cold-chain-anomaly-detection/actions/workflows/run.yml)

**Catch failing freezers and open doors from temperature sensors using unsupervised ML plus a hard rule.**

> **About the data:** everything in this repo is simulated, generated by the code with a fixed random seed so results are reproducible. The numbers describe the simulation, not the real world. Each project says how to swap in a real dataset.

## The business question

Can we flag a failing freezer or a door left open before stock is lost, without drowning the site manager in false alarms?

## What this project does

Cold stores log temperatures every few minutes, but nobody reads the logs until something has already spoiled. This project builds rolling features from sensor readings, flags unusual behaviour with an Isolation Forest plus a simple out-of-spec rule, and groups alerts into incidents with a start, end, peak and duration.

## The data

12 rooms (7 chillers at a 3 C setpoint, 5 freezers at -20 C) read every 5 minutes for 30 days in September 2026, which is 103,680 readings. Normal noise is about 0.3 C. Freezers have 20-minute defrost bumps every 6 hours, which are normal and should not alert. Injected faults: door-open spikes (1 or 2 per room, ramping +8 C over an hour) and two slow compressor failures (rooms R02 and R09, drifting +9 C over about 25 hours). The code tracks these as ground truth.

## How it works

1. Per-room features: deviation from setpoint, 1-hour rolling mean and standard deviation, 15-minute change and 1-hour mean deviation.
2. Fit one Isolation Forest per room type (chiller, freezer) with 2% contamination.
3. Hard rule: temperature outside spec (chiller 0 to 5 C, freezer -25 to -15 C) for 6 consecutive readings (30 minutes).
4. Alert = rule fires OR the Isolation Forest flags 3 consecutive readings (to cut noise).
5. Group consecutive alert readings into incidents with start, end, peak temperature and duration.
6. Score against the injected ground truth: precision (share of incidents overlapping a real event) and recall (share of real events that raised at least one alert).

## Run it

```bash
git clone https://github.com/harsha089999/cold-chain-anomaly-detection
cd cold-chain-anomaly-detection
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python src/main.py
```

It runs in about 15 seconds or less on a laptop and writes its files to `outputs/`. Python 3.10 or newer is recommended.

## Results from the included run

This is the actual console output when the script is run as shipped:

```text
Incidents raised: 36  precision: 58%  recall: 100% of 20 real events
```

Every one of the 20 injected events was caught (100% recall), but only 58% of incidents overlapped a real event, so about 15 of the 36 incidents are false alarms. That is too noisy for a real site. Tuning the contamination rate, the persistence rule, per-room models and defrost-aware features is the obvious next step.

## Output files

| File | What it contains |
|---|---|
| `outputs/incidents.csv` | One row per incident: room, start, end, peak temperature, readings, duration, and whether it overlapped a real event. |
| `readings_scored.csv` | Generated locally in `outputs/` (about 16 MB, so it is git-ignored): every reading with features and flags. |

## Limitations and honest caveats

- The injected faults are easy to see. Real sensors drift, drop out and have site-specific door patterns.
- The model is fit and scored on the same month (normal for unsupervised detection, but not a forward-looking test).
- Spec limits here are illustrative. Use your own food-safety (HACCP) limits.
- Precision of 58% means roughly 4 in 10 alerts would be a wasted call-out.

## Using real data

Replace `make_data()` with a loader returning `ts, room, kind, setpoint, temp_c` (and no `true_event` column, or keep one if you have labelled incidents).

## Turning it into a dashboard

Small multiples of temperature per room with alerts highlighted, an incident log table and a 'minutes out of spec this week' KPI by site.

## Ideas to extend it

- Forecast-residual detection (predict the next reading, alert on large errors).
- Defrost-aware features.
- Send alerts to Teams or email.
- Estimate stock value at risk per incident.

## Skills demonstrated

Unsupervised ML, time series feature engineering, alert tuning (precision vs alert fatigue), operational reporting.
